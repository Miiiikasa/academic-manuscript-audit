# Submission package, format and cross-file audit

## Inventory and completeness

Scan the specified folder or file list read-only. Show the filenames, count,
provisional roles and versions. Separate candidate count from confirmed count,
and mark incomplete scans. Inspect named subfolders when the user includes
them. Exclude backups, Word lock files, old versions and unrelated material.
Confirm the intended set when necessary. Ask about quantity only if the
directory cannot be fully scanned or the scan conflicts with the user's
description. Record version facts and stable fingerprints where useful.

| File or field | Role | Version / extension / size | Included or excluded | Required condition and source | Evidence / status |
|---|---|---|---|---|---|

Match the confirmed inventory against the journal rule ledger. Check accepted
file extensions, naming, version, readable content, duplication and limits.
Distinguish separate uploads, information accepted inside another document,
and portal-only fields. Typical candidates include a manuscript, title page,
supplement, figures, tables, cover letter, highlights, graphical abstract,
significance statement, declarations and data/code information. Require each
only if the applicable rule does. Check whether a selected file opens and
actually contains the intended material. A filename alone does not suffice.
Use the [file status decision table](report-contract.md#file-evidence-and-partial-scope)
for missing, pending, unreadable and inapplicable artifacts. At revision stage,
identify clean, marked and response materials with
[follow-up and revision](re-audit-and-revision.md).

## Anonymisation and authorship presentation

Apply the verified review model to each reader-facing file and portal field.
Inspect the title page, manuscript, supplement, figures, filenames, file
properties and metadata where tools permit. Check authors, affiliations,
acknowledgements, funding, identifiable repository links, self-references,
comments, tracked changes, reviewer annotations and embedded objects.
Protect anonymous and identified versions separately. Report an identity leak
only under an applicable policy and with exact location. Intentional
differences required by blinding or portal routing are legitimate.

On identified files, compare name spelling and sequence, affiliation markers,
corresponding author, email, ORCID and funding identifiers. Author approval
of roles, identity, disclosures and final versions remains separate from
cross-file agreement. See [integrity and availability](integrity-and-availability.md).

## Front matter, structure and Cover Letter

Check title scope and any title formatting rules. Check abstract structure and
limits, keyword count and presentation, Highlights, graphical abstract and
significance statement separately when relevant. Check section organisation,
heading hierarchy, page and line numbers, font,
spacing, margins, manuscript length and counting exclusions where specified.
Record the counting method and its coverage. Preserve accepted article
structures and journal-permitted formats. If the journal offers format-free
initial submission, separate the current requirements from later production
expectations.

Check that a required Cover Letter identifies the intended journal and article
type and agrees with the current title, corresponding author, study scope,
claims and declarations. Inspect claims of exclusivity, prior dissemination,
related submissions and author approval as statements to verify with the
author. Do not presume them true or require a conventional letter when the
official guidance uses a portal field or makes the letter optional.

## Cross-file reconciliation

Build a ledger for title, article type, author data, terminology, sample
sizes, key results, units and denominators, figures and tables, references,
disclosures, repository identifiers and versioned links. Compare equivalent
populations, analyses, time windows and precision. Distinguish an intentional
short title, masked copy, valid rounding and supplement-only analysis from a
real mismatch. Record both locations, the apparent source of truth and all
affected occurrences. If a file was not provided or a source is unresolved,
scope the result and report the gap. Cross-reference the primary checklist
item for the same discrepancy instead of raising the same finding under
multiple headings.

|---|---|---|---|---|

## Final presentation and hidden content

Render the actual submission files or available proof when feasible, with
read-only tooling. Inspect pagination, blank or missing pages, table and
caption breaks, figure attachment, clipping, fonts and equations, placeholder
text, field display and links. Inspect hidden text, comments, revisions,
author metadata and embedded objects where accessible. Distinguish Word
extraction, local rendering, and the system's generated proof. A clean local
export does not validate the portal proof. Use page numbers only when
verified, and use section, paragraph or table/cell locators otherwise.
