# Checklist and recommendations contract

Write two Markdown files to the requested directory. By default use a new
run folder inside `Pre-submission_Audit` beside the confirmed package. State
the destination and preserve earlier runs. Use the user's language for prose.
Keep the five result labels as specified below. A non-Chinese report may
include an explanatory glossary once. The starting schemas are
[Submission Checklist.md](../templates/Submission%20Checklist.md) and
[Issues and Recommendations.md](../templates/Issues%20and%20Recommendations.md). A requested benchmark
outputs [Recent_Publications_Benchmark.md](../templates/Recent_Publications_Benchmark.md),
alone or alongside the audit. When the optional module is skipped, state
that scope limitation and omit all sample conclusions.

Both audit reports identify mode, article type, stage if known, the reviewed
versions, and limits of extraction, external verification and access.
Mode A reports the complete confirmed scope. Mode B reports the requested
subset and does not imply whole-package approval. Report relevant checks
even when unresolved. For a [follow-up](re-audit-and-revision.md), identify
baseline and current versions and report only new, changed and still-open
items. Use an aggregate closure count if useful. Keep outlines and ledgers
as working material. Include a brief editor or reader observation only when
it explains a concrete issue.

## Checklist decisions

Use columns ID, check, authority, result, location, severity and notes.
Record evidence and coverage in the notes. Link rule IDs to the journal
source ledger and findings to their issue IDs. Use one decidable criterion
per row, with a separate row when a different file, authority or observation
could yield a different result. Distinguish an explicit journal requirement,
journal recommendation, general scholarly norm and optional improvement.
An editor's preference and an observed publication practice have no force
as submission rules.

| Result | Use it when |
|---|---|
| 通过 | The applicable check was performed and the observed evidence meets it, within the stated coverage |
| 未通过 | Evidence shows a concrete defect against an applicable criterion. An optional stylistic opportunity by itself is not a compliance failure |
| 待人工确认 | A human decision, permission, author-only fact, version choice or factual confirmation remains necessary |
| 不适用 | The criterion is outside the agreed scope or its triggering condition demonstrably does not apply. Record why |
| 无法检查 | The necessary source, artifact, rendering or technical access is unavailable. Say what could still be inspected |

Use these labels throughout both reports. Record a scientific decision
requiring author input as 待人工确认. Record an unreadable figure, ambiguous
extraction without a reliable view, or unavailable official source as
无法检查. A visible mismatch can be 未通过 even when the correct value is
separately 待人工确认. Keep confidence and severity distinct from result.

If no explicit journal rule was found, record the scope of the search.
Use 不适用 for an absent mandatory criterion only when applicability has
been established from sufficient evidence. Use 无法检查 if incomplete access
prevents deciding. A general assessment may be recorded separately. Never
treat an inaccessible portal, unverified statement, unresolved conflict
or unchecked part of a sample as passed. Add Markdown task items for open
checks with their IDs and closing evidence. A checkbox records a recheck
action and does not substitute for a result.

## File evidence and partial scope

| Situation | Result and reason |
|---|---|
| The applicable rules require the file at the current stage and its absence from the current package is confirmed | 未通过, including when it has not been prepared and the author plans to add it later. Record the rule, confirmed absence and next action |
| Whether the file is required, its role or the submission stage still needs a human decision | 待人工确认. Name the fact that would resolve applicability |
| The file exists but cannot be opened, extracted or rendered | 无法检查 for the content check. Its presence can be confirmed separately |
| Directory access is partial and absence cannot be established | 无法检查 for the inaccessible inventory. Do not infer a missing file |
| The applicable rules do not require this file for the journal, article type and stage | 不适用 for the required-file check. Cite the applicable condition or exception |

Report the confirmed subset without waiting for files to be prepared.
Label both reports provisional or scoped, list material outside that scope,
and record what would close each gap. State whether the verified scope
contains a blocker, has open conditions, or is insufficient to judge.
Avoid a full readiness conclusion from a partial audit.

## Issue severity and content

- **P0** — credible obstacle to submission, material violation of a verified
  mandatory rule, or serious scientific or integrity risk supported by evidence.
- **P1** — identifiable submission, formatting, file or cross-reference defect
  that should be resolved before submission and does not have P0 consequences.
- **P2** — an optional professional, readability or presentation improvement
  with a concrete benefit.

Assign severity from applicability, actual consequence and confidence.
Priorities from the historical checklist do not carry over. Show an
unconfirmed possible blocker as a pending verification with its conditional
impact. Keep it separate from confirmed violations. A compliant passage can
still have a P2 improvement without being marked 未通过 in the checklist.
Style or argument polish is normally P2. Raise priority only when the
evidence shows a concrete comprehension, support or compliance problem.
An optional personal preference need not be reported.

Order confirmed findings and actionable recommendations by P0, P1 and P2.
For each, give the ID and related checklist rows, file, stable location,
observed problem, verified requirement or reader impact, suggested action,
author confirmation, and any synchronisation sites. Use evidence confidence where it matters.
High means direct or corroborated evidence. Moderate means a credible
finding with a named limitation. Insufficient evidence belongs in the open
checks rather than as a confirmed violation. Include a short exact excerpt
only when it helps identify the problem. For figure label conflicts,
show both forms and the panel. For edits that would change scientific
meaning or terminology, specify the decision to confirm.

Describe **what to change and where**. Do not supply a replacement sentence
in any language, a rewritten caption or paragraph, or a ready-to-paste
draft. Specific metadata conflicts may be listed with the observed values
and source. Do not rewrite the manuscript, even when the solution appears
routine. Merge multiple manifestations of the same root cause and retain
all affected locations. There is no quota. Prefer fewer evidenced findings
to speculative or optional edits. A possible alternative is not evidence of
a defect. Say explicitly when no issues were found in the inspected scope.
List remaining human and technical checks separately, with responsible
party and closing evidence.
