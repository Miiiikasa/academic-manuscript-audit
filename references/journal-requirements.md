# Journal intake and evidence

## Ask for missing intake information

Follow the [full-audit intake gate](../SKILL.md#full-audit-intake) for
user-facing questions and confirmation. A user-confirmed file list or an
unambiguous instruction to include the enumerated files satisfies package
confirmation. If the user has no local guide or asks you to use the official
guide, look it up directly. If the user has a local guide and its path is
missing, ask for the path. An access limit discovered after intake is an
evidence limitation. Apply the status rules below.

Resolve journal identity using official title and, when necessary, website or
ISSN. Determine the article category used by the journal. Record initial
submission, revision, transfer or production if it changes the rules. Find
the review model, study-design conditions and any relevant special-issue or
editor instructions from reliable evidence. Ask only when the distinction
could change the outcome.

## Find, rank and cite the rules

For each applicable rule, use this precedence:

1. Current official Guide for Authors and clearly applicable journal policies.
2. Official journal instructions for artwork, references, supplements, research
   integrity, peer review and submission systems, including publisher policy
   pages the journal actually adopts.
3. Author-supplied guide files.
4. General scholarly publishing or disciplinary norms.
5. Historical checklists and house preferences.

Find the current guide on the official journal site even when a local copy
is supplied, where access permits. Record the local document version or
visible date, the official URL and access date, and meaningful differences.
Check article-type pages, first-submission exceptions and linked policies.
Within official sources, apply a documented exception that explicitly governs
this article type or stage. Record unresolved conflicts between official
sources with both locators and the precise question for the author or editor.
A publisher's guidance is not necessarily adopted by every journal.
Observed practices in published papers belong in a separate benchmark
evidence category. They do not enter the rule hierarchy or alter an explicit
submission requirement.

Read the relevant passage in its context. Classify each item as **explicit
journal requirement**, **journal recommendation**, **general norm**, or
**optional improvement**. An official page can contain all four. A requirement
in a local guide that could not be corroborated should be identified as local
or provisional. A check against that copy can describe what it found. Mark
compliance with the current official rule **无法检查** when access is
insufficient. A historical checklist supplies candidate checks
and never supplies a journal mandate. Discard penalty schedules and
publisher-wide assumptions without current authority.

| Rule ID | Authority and category | URL or local guide | Section / page / anchor and access date | Type / stage / condition | Requirement and any conflict |
|---|---|---|---|---|---|

Assign a stable rule ID to each journal-specific requirement used in the
checklist. Record the precise threshold and how it is counted or measured.
Cite actual headings or page numbers where available. If no explicit rule was
found, say so and distinguish a completed search of the relevant pages from
a lack of access. Do not invent a threshold or mark the requirement passed.

## Portal and access limits

Public help can establish documented portal requirements. A user's approved
screenshots or a permitted read-only view of the selected article category
can establish what those screens show. They do not confirm unseen upload
slots, generated proofs, required metadata or validation at later steps.
Never create a draft, upload files, press submit, transmit unpublished text,
or ask for a password or token to complete an audit. A missing author-only
setting is **待人工确认**. An inaccessible authoritative source or unavailable
technical inspection is **无法检查**. Say what would resolve it. Continue with
checks supported by available evidence.
